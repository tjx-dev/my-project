# 第 5 步① 异常情况检查

本次检查错误输入、TCP 断开、数据库连接失败和 CSV 保存失败后的恢复操作。

## 本轮修复

| 触发情况 | 修复后的表现 |
|---|---|
| 历史查询因数据库连接断开而失败 | 清空旧查询结果，恢复账号、密码和连接按钮 |
| 收到未登记的设备编号 | 数据处理结果显示忽略原因，计数保持原值 |
| 收到错误的温度格式 | 显示输入要求，连接断开后仍保留错误原因 |
| 模拟器连接失败或连接中断 | 显示具体原因，恢复开始按钮，允许重试 |

数据库保存失败时，监控表格仍显示已收到的温度。界面提示本条未保存，重新连接成功后保存后续收到的数据。

## 你先亲手检查这一组

1. 双击 `D:\codex\2026-11-02\q\industrial-device-monitor\tools\open-monitor-and-simulator.cmd`。
2. 在监控窗口点击「开始 TCP 接收」。记住当前总记录数。
3. 在模拟器输入 `A,abc`，点击一次「发送数据」。监控窗口的数据处理结果应显示格式错误，总记录数保持原值。
4. 改为 `Z,90` 再发送一次。应显示未登记设备，总记录数保持原值。
5. 改为 `A,84` 再发送一次。设备 A 显示 84 度，总记录数增加 1。
6. 改为 `A,85` 再发送一次。设备 A 显示高温告警，总记录数再增加 1。

模拟器的「已发送」表示字节已经发出，是否形成有效温度记录，要看监控窗口的数据处理结果。

## 再检查断开和重连

1. 监控窗口正在接收时，在模拟器点击「开始定时发送」。
2. 在监控窗口点击「停止」。模拟器应停止定时发送、显示连接中断原因，并恢复开始按钮。
3. 监控窗口重新点击「开始 TCP 接收」，模拟器重新开始定时发送。温度和次数应继续更新。

## 自动测试已经覆盖的情况

- 半条记录分段到达、多条记录同时到达、多个客户端交错发送。
- 断开后重连，旧缓冲区中的半行被清除。
- 一条连接发送超长数据时，其他连接仍能正常发送。
- 错误格式、越界温度、未登记设备，以及 -50 和 150 两个合法边界。
- 模拟器首次连接失败，以及连接中断后的重试。
- 数据库连接被断开后，查询和保存的失败提示、重新连接、错误密码后再输入正确密码。
- CSV 取消保存、目标目录失效、失败后重试，以及导出内容和明细一致。

会写数据库和中断数据库连接的测试在独立的 13316 端口测试实例中运行。测试拒绝使用日常的 3306 和项目的 3307 端口。

## 本次代码看哪里

- `src/tcp_receiver.cpp` 的 `readData()` 检查每行数据，通过 `dataRejected` 通知窗口显示错误原因。
- `src/mainwindow.cpp` 的 `handleDatabaseFailure()` 关闭失效连接、清理旧结果并恢复输入框。
- `simulator/widget.cpp` 的 `errorOccurred` 回调显示连接错误并停止定时发送。

先能描述触发条件、提示和重试步骤，再对照代码找到这三个动作。
